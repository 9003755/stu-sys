# 验收与回归测试计划

更新：2026-10-12。适用于交接后的日常修改和发布，最新执行结果写入 [STATUS](../STATUS.md)。以下“验收标准”是待执行的检查要求，不代表所有项本次都已实机验证。

## 1. 测试层次与命令

按 [部署手册](DEPLOYMENT_RUNBOOK.md) 安装依赖和准备环境。所有测试从仓库根目录运行。

```sh
npm ci
npx playwright install chromium
npm test
npm run check:docs
npm run lint:tools
npm run build
npm run lint
```

| 命令 | 覆盖内容 | 不能证明的内容 |
| --- | --- | --- |
| `npm test` | 下载超时/重试/离线/取消、队列、缓存与 ZIP 内容，Node 内置测试运行器 | 相机硬件、真实 RLS 和线上网络 |
| `npm run test:browser:zip` | 隔离假数据页面、临时文件服务、真实浏览器 UI 与 ZIP 校验 | Supabase 登录、真实班级、真实图片识别或邮件发送 |
| `npm run check:docs` | 文档引用与交接材料的静态检查 | 文档描述是否已在线上执行、账号授权是否完成 |
| `npm run lint:tools` | 维护脚本与自动测试的 ESLint（Node 与浏览器回调环境） | 业务 src 历史 lint 债务是否清除 |
| `npm run build` | 生产构建、依赖和静态资源生成 | 数据库/函数是否部署、真实业务是否正常 |
| `npm run lint` | 全仓代码规则检查 | 功能正确性；当前历史失败需单独登记 |

浏览器测试使用 `tests/classDocumentArchive.browser.mjs`，需要先启动 Vite。终端一保持运行：

```sh
npm run dev -- --host 127.0.0.1 --port 5173 --strictPort
```

终端二执行：

```sh
npm run test:browser:zip
```

若指定 `ZIP_TEST_URL`，须指向本地 Vite 开发服务，不能指向生产地址。默认使用 Playwright `1.62.1` 配套 Chromium；需要本机 Edge 时 PowerShell 设置 `$env:ZIP_TEST_CHANNEL = 'msedge'`，POSIX 使用 `ZIP_TEST_CHANNEL=msedge npm run test:browser:zip`。Linux 可用 `npx playwright install --with-deps chromium` 安装系统依赖。截图/ZIP 写入系统临时目录 `student-system-zip-qa`，只含 fixture 假数据。测试包含实际 48 秒慢流，运行超过一分钟是正常现象。

本次交接前的业务基线已有 30 项 Node 测试通过，浏览器覆盖过实际 48 秒持续传输、失败重试、断网恢复、暂停继续、重复保存、桌面/手机布局和 ZIP 目录。全仓已有 lint 债务，不能把局部 eslint 通过写成全仓通过；最新数量及文件以 `STATUS.md` 及命令结果为准。

## 2. 测试数据与环境

使用单独的 Supabase 项目和 HTTPS 测试前端。准备普通管理员 A/B、超级管理员、测试班 A/B、已报名/未报名/同名学员，以及带“测试资料”水印的两张 A4 图片和身份证/证件照样图。记录这些测试对象的 ID 与所属项目，避免用姓名猜测待删对象。

生产冒烟默认只看页面、配置和已授权数据。覆盖资料、修改姓名、删除学员、重置密码、创建账号、群发或触发容量邮件均不能用真实用户做随意试验。删除测试前保留隔离数据快照，测试后仅清理明确创建的测试对象。

## 3. 核心业务验收矩阵

| 编号 | 操作 | 通过标准 |
| --- | --- | --- |
| A01 | 学员、普通管理员、超级管理员分别登录/退出；同标签页切换角色 | 使用各自会话，权限互不串用；退出和关页后的状态符合 sessionStorage 行为 |
| A02 | 桌面 Chrome/Edge 登录管理员；断网、错误密码、过期会话后重试 | 正常可入后台；失败有明确提示，不无限加载；检查 auth、admins 请求分别耗时 |
| A03 | 直接打开并刷新 `/super/login`、`/admin/dashboard` | 路由资源可达；无权限用户不能读取受保护数据 |
| A04 | 学员填档案、分别上传证件照/身份证正反面，相册或系统相机返回 | 已填字段和图片状态不丢失；保存可重新打开；`?uploadDebug=1` 可辅助定位学员档案上传 |
| A05 | 管理员 A 建测试班并报名；管理员 B 读取/修改 A 班 | A 可管理自身数据，B 的直接 API 请求也被拒绝，不能只验证 UI 隐藏 |
| D01 | 班级资料按钮生成二维码，未登录手机扫码 | 打开 `/class-documents/<accessToken>`；不要求学员账号，最终提交与指定班级关联 |
| D02 | 同色/深色背景拍两张独立 A4，分别拖动四角 | 黄框仅引导，不阻止拍照；两份均确认才能提交；扫描预览裁掉外围背景、正文完整且清楚 |
| D03 | 网页相机拒绝权限或不可用，切系统相机/相册 | 有可执行的替代入口；取消不影响另一份资料；支持的图片每份不超过 12MB |
| D04 | 唯一匹配本班姓名，确认本班学员后保存，再以同姓名重交 | 提示已归档；一名学员最终只有当前两份；旧资料被替换，页面状态正确 |
| D05 | 不存在姓名、含空白姓名、班内同名姓名提交 | 无唯一匹配时进入“待核对姓名资料”，学员看到未匹配提示；不能伪装成已匹配成功 |
| D06 | 管理员对待核对项选择正确学员，或删除 | 正确归档或删除，核对后记录不再 pending；不能强行归到另一班 |
| D07 | 预览、单独下载、替换、删除两份资料 | 文件对应人/类型；删除后刷新仍消失；数据库与 Storage 分步失败得到正确诊断 |
| Z01 | 下载全班 ZIP、解压检查 | `班级/学员/学员+无犯罪记录.jpg` 和 `学员+身体健康申明.jpg`；数量等于已匹配提交人数 × 2，无 pending 或未提交记录混入 |
| Z02 | 限速使单份持续下载超过 45 秒；中途临时失败/断网再恢复 | 有数据流入时不触发旧 45 秒总时限；自动重试、联网恢复，最终完整 ZIP |
| Z03 | 一份永久 404；暂停后继续；生成后再次保存 | 不导出残缺 ZIP；完整成功文件复用；再次保存不重新获取文件 |
| Z04 | 下载时切班/离开页面/刷新 | 旧任务取消、内存缓存释放；重新进入重新下载，不承诺跨页恢复 |
| S01 | 超管在隔离环境单删和批量删已报名学员 | auth/profiles/enrollments 等关联一致，非目标用户保留；Storage 对象也需独立核对，不能只看 UI 消失 |
| E01 | 导出报名 Excel、题库账号数据、身份证 PDF 和资料 ZIP | 模板列、中文、排序、考试类型、身份证拼接及文件目录符合业务要求；抽查缺资料学员 |
| O01 | 容量统计只读检查；获授权后隔离收件地址测试邮件 | RPC 返回正确；函数 slug、cron、Secrets 一致；邮件实收才算发信通过 |

D05 中姓名规范化会移除空白并转换大小写；同名多匹配不能靠姓名自动判定。D06 的当前下拉只列未归档学员，已归档对象的冲突处理需要先核实实际需求，不能假设 UI 支持任意覆盖。

## 4. 设备和网络矩阵

至少在桌面 Chrome/Edge、iPhone Safari、Android Chrome、Android 微信内置浏览器执行 D01–D04；有实际使用者时补测三星/夸克。记录手机型号、系统版本、浏览器版本、网络运营商、是否 HTTPS，以及成功/失败步骤。桌面模拟手机尺寸不能替代真机相机、权限或相册返回测试。

网络分别覆盖正常、慢速、离线后恢复；扫描生成主要是本机 Canvas 运算，图片上传和 ZIP 获取主要依赖网络，须分开计时。当前扫描输出 1654 × 2339 JPEG，使用手动角点及透视变换，不做 OCR。检查中文小字、纸张四角、印章和边缘是否被截掉。
