# 学员、普通管理员与超级管理员操作手册

更新时间：2026-10-12，对应业务代码 `eb1df86`。正式站点：[stu-system.netlify.app](https://stu-system.netlify.app)。凭据由项目负责人通过私密渠道移交，本文不记录密码。

## 1. 先区分两个二维码

| 二维码 | 用途 | 是否登录 |
| --- | --- | --- |
| 班级报名二维码 | 注册/登录、档案填写、报名 | 需要学员账号 |
| 资料收集二维码 | 本班无犯罪记录及身体健康申明 | 不登录，填写姓名 |

二维码不能互相代替。管理员分发时注明班级和用途；资料上传页当前不显示班级名，应以发放说明为准。

## 2. 学员报名与修改

1. 扫班级报名二维码，已有账号登录，新学员注册。
2. 填写个人信息、联系方式、地址、报考类型等必填项，分别上传身份证正反面、证件照，档案图片每张不得超过 15 MB。
3. 检查信息和图片后保存，按提示确认报名，看到完成状态再离开。
4. 修改时使用报名页“修改报名资料”，或原账号登录个人档案，保存后让管理员刷新核对。

相册返回后等待图片上传完成，避免反复刷新。草稿恢复不能替代“保存成功”。权限不符先检查学员/管理员角色；学员忘记密码请管理员重置。

## 3. 学员提交两份 A4 资料

### 准备

准备两张独立纸张/照片，每张一类，不得合并。铺平纸张，光线均匀，避免手指、反光、阴影。手机尽量平行纸面，纸张占据较大画面，等图像清晰稳定再拍。

推荐更新的 Safari/Chrome；微信内相机失败可点系统相机，或复制链接到系统浏览器。网页相机需 HTTPS 和相机权限。纸张与背景颜色近似不会阻止拍摄，黄框只是构图参考。

### 提交步骤

1. 扫本班资料收集码，不用账号密码。
2. 在“无犯罪记录”选择“从相册上传”或“拍照上传”。相册图片不超过 12 MB；网页相机失败可点“系统相机”，原生相机没有网页黄框。
3. 拖四个蓝点贴住纸张左上、右上、右下、左下角，不交叉，也不要只围文字部分。
4. 点“确认四角并生成扫描件”，检查四边完整、文字清晰、裁切正确；不合格点“重新选择”重新拍/选。
5. 对“身体健康申明”重复同样步骤，两份均生成扫描件后填与报名一致的姓名。
6. 点“确认并保存上传”，确认自己属于本班，保持页面打开直到明确结果。

“生成扫描件”是在手机处理图片，“正在上传”才是传给后台。选准四角无法让失焦照片变清晰，提交前应放大检查小字与签字。

### 结果与补交

- “资料已提交成功”：姓名唯一匹配本班报名，管理员可查看，仍需人工质量复核。
- “姓名未在本班级名单中匹配……待核对”：文件已收到但未归档，请联系管理员核对错名或重名；不是正式归档成功。
- “二维码无效”：向管理员重新获取链接，不修改令牌。
- 替换已交资料：重新打开原二维码，以相同正确姓名重新提交两份，覆盖旧提交。学员端不支持只补一份或恢复旧版本。

## 4. 普通管理员：班级和报名

进入 [普通管理员登录](https://stu-system.netlify.app/login?role=admin)，工作台包括“班级管理”“学员列表”“资料收集”。

### 班级管理

1. 点击“创建新班级”填写名称、说明、开班日期、状态。
2. “班级报名二维码”用于报名；绿色“资料收集二维码”用于两份 A4，弹窗可打印并显示链接。
3. “资料提交”列显示已交/总数、未交、待核对；点数量进该班资料页。
4. 删班前系统检查报名数，非空会阻止。不要为删班先批量删除真实报名，先确认影响。

当前没有通用班级编辑界面。若看到他人班级或自己的班级缺失，交维护者查归属与权限，不自行改授权。

### 报名审核与导出

在“学员列表”筛班、查详情、审核、修改报考类型、重置学员密码。选中学员后：

- 下载报名资料：先检查档案必填项，缺项按提示补全；ZIP 含 `stu/stuIm.xlsx` 和 `stu/stuPicture/`。
- 下载身份证：生成正反面 PDF，多人按页面行为打包。
- 下载题库账号：生成题库账号 Excel。

这些旧导出与资料收集 ZIP 不同，没有同样的暂停续传，失败图片可能缺件，完成后检查人数和照片数。普通管理员学员列表“删除/批量删除”删的是报名，不是学员全局账号；账号注销请超管处理。

### Excel 模板筛列工具

独立入口 `/tools/excel-template-filter` 用于处理本地 Excel：选择源文件，查看源表列与报名模板表头的匹配情况，再生成按模板顺序排列的新文件。工具不会把文件导入学员数据库。生成后核对行数、缺失列和内容，保留原文件；具体列规则见 [模板工具说明](EXCEL_TEMPLATE_FILTER_TOOL.md)。

## 5. 资料预览、替换、纠错与删除

进入“资料收集”选班，点“刷新”获取新状态。每名学员显示“已提交两份/未提交”；班级首页统计需重新进入班级页更新。

| 操作 | 作用 | 注意 |
| --- | --- | --- |
| 预览 | 看单份扫描件 | 检查姓名、内容、签字、清晰度和裁切 |
| 下载 | 保存单份 JPG | 名称为姓名+资料类型 |
| 替换 | 管理员换对应一张图 | 12 MB 内，转 JPEG，无四角编辑，请先准备合格图片 |
| 删除 | 删除一条提交及两份资料 | 不是只删除一张，先核对对象 |

不合格资料由管理员自行通知学员重交，目前无自动催办消息。

### 待核对姓名

待核对区显示提交姓名，可预览/下载两张图。正式学员行没有资料时，先检查这里。

1. 确认是本班学员写错：在“修改为正确姓名”选择正确学员，资料归档并退出待核对；不会修改全局档案姓名。
2. 确认不是本班或无效：选择删除并确认。

下拉仅列尚无匹配资料的本班学员。正确学员已有合格资料时先核查两次内容、下载需要保留的文件，再联系维护者或让学员用正确姓名重交，不随意删除旧资料。重名也会待核对，不能仅凭姓名认领。

管理员必须完成归档/删除之一，但页面不会强制阻止留下待核对，所以收集结束要人工检查待核对数为零。

### 删除报错

- “不存在或无权删除”：刷新确认对象和账号，交维护者查，不反复点。
- “记录已删除，但图片文件清理失败”：记录已经删除，不能靠重复删记录清理对象。记时间、班级、错误，通过私密渠道给维护者检查 Storage。
- 删除不能用浏览器撤销恢复，恢复需负责人按备份手册处理。

## 6. 全班 ZIP：慢网、暂停与继续

1. 在资料页选班，核查已提交数/待核对，点“下载全班 ZIP”（旧界面可能叫“下载全部 ZIP”）。
2. 看已完成份数、接收体积及当前文件。持续慢速有数据时继续等，短时故障自动重试，浏览器识别断网会等恢复。
3. 可点“暂停”，保持本页，再点“继续下载缺失资料”。完整文件不用重取，未传完的一份重新下载。
4. 失败时展开“查看未完成原因”，网络恢复后继续；全部目标齐全才生成 ZIP。
5. 显示完整 ZIP 已生成并发起保存后，检查浏览器下载列表。未开始保存可点“再次保存 ZIP”，不用重新联网。

**刷新、关闭、切班或切到其他工作台 Tab 会清空本次缓存。** 手机锁屏/后台也可能暂停浏览器，较大班级建议电脑前台操作。

```text
培训一班.zip
└─ 培训一班/
   └─ 示例学员/
      ├─ 示例学员+无犯罪记录.jpg
      └─ 示例学员+身体健康申明.jpg
```

ZIP 只含已匹配，不含未提交或待核对。解压核对目录数与已交人数、每人两份。**同班有同名学员时暂勿依赖全班 ZIP**：现有姓名目录会冲突，应分别下载人工区分，等待维护者消歧修复。

永久断网、对象删除、无权限或内存不足不能靠等解决，保留原因交维护者。单份下载目前没有上述续传，失败后可再点。

## 7. 超级管理员

入口 [超级管理员登录](https://stu-system.netlify.app/super/login)。负责人私密移交账号及现行登录方式。当前二段验证仍是前端演示，不会真发邮件验证码；不要把收不到邮件当邮箱故障，维护者应优先加固为真实服务端 MFA。

超管可查管理员及班级、重置密码、全量学员搜索、处理无效账号/无主班级。创建管理员可能切当前会话，按提示重登超管。

| 删除入口 | 影响 |
| --- | --- |
| 普通管理员资料页 | 一条提交与两份资料 |
| 普通管理员学员列表 | 选定报名记录 |
| 超管学员页 | 全局账号及关联数据，可能影响多班 |
| 超管管理员删除/数据救援 | 班级归属和关联数据，按运维手册备份确认 |

危险删除有加强确认，不使用真实学员做测试。不能因提示文案称删除全部图片而省略 Storage 实际验证。权限、救援、SQL、备份恢复由获授权维护者执行。

## 8. 故障反馈

记录时间、入口类型、设备/浏览器版本、卡在加载/扫描/上传/下载的哪一步及完整错误。截图遮盖姓名、证件号、电话及私有图片；资料令牌/签名链接仅私密提供。

| 现象 | 先做什么 |
| --- | --- |
| 扫码一直加载 | 确认管理员 HTTPS 链接，换系统浏览器/网络；尚未选资料可刷新，上传/打包中不要直接刷新 |
| 相机打不开 | 允许权限、用系统相机/相册，检查不是 HTTP |
| 裁切不准 | 四角贴纸边，模糊或缺边重拍 |
| 上传后找不到 | 看返回结果和本班待核对，核对姓名/重名 |
| 登录长期加载 | 记角色/入口/报错，维护者分认证、权限、资源请求 |
| ZIP 某份失败 | 保持本页，展开原因并继续缺失资料，别先刷新清缓存 |

技术排查从 [交接入口](HANDOVER.md) 与 [CODE_WIKI.md](CODE_WIKI.md) 开始，处理结果记入状态文档。
