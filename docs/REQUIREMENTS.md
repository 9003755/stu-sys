# 需求基线与当前实现对照

更新时间：2026-10-12。需求来源为本项目用户已确认的会话决定，代码核对基线为 `eb1df86`。本文件区分用户要求、现有行为与待验收事项，不把代码存在等同于生产验收通过。

## 1. 业务目标与角色

系统用于培训机构报名、档案采集、班级管理及导出。普通管理员管理自己创建的班级；超级管理员负责全局账号和运维。新增匿名资料收集不取代原有需要账号的报名。

两类资料名称固定为“无犯罪记录”“身体健康申明”，是两张独立 A4 纸，每班每名学员都要交两份，不允许合并成一张图片或一个合并文件。

| 编号 | 已确认需求 | 当前实现及边界 |

## 3. 不应无意改变的产品决定

### 手动四角

用户已明确取消自动入框检测，后续不可为“自动化”恢复强制检测门槛。黄色框用于位置参考，实际裁切以拍后四角为准；自动四角识别若新增，应先确认需求，并保留人工调整。

扫描输出当前为 `1654 × 2339` JPEG，不含 OCR、阴影消除、签名/真实性校验或自动去模糊。质量依赖原始照片、四角和管理员复核。

### 匿名姓名匹配

免登录是明确选择，不等于身份验证。持有二维码并知道姓名者可能覆盖对应资料；当前没有短信验证、防重放、公开配额或不可篡改版本审计。二维码只向本班发放，未来增加认证或期限需重新确认。

### 纠错、替换和删除

“修改姓名”是把 pending 关联到正确报名，不修改全局档案姓名。下拉仅列尚无匹配资料的本班学员；正确学员已有资料时，管理员应确认保留内容，下载必要备份后处理，不可随意绕过 UI 改库。

资料页删除同时删除一条提交和两份资料；只改一张用“替换”。普通管理员学员列表删除的是报名，超管学员删除是全局账号，两者影响范围不同。

## 4. 文件与数据验收规则

正常提交后的验收：

1. 当前报名只有一条匹配资料记录，两条图片路径可读；重交后已交人数不重复增加。
2. 正式学员行显示已交两份；单份文件名为正确姓名加资料名称。
3. 待核对不计已交、不入正式 ZIP，管理员能查看提交姓名及两张图片。
4. 缺失文件未下载完时不输出“完整 ZIP 成功”，保留失败原因并允许继续。

```text
班级名称.zip
└─ 班级名称/
   └─ 学员姓名/
      ├─ 学员姓名+无犯罪记录.jpg
      └─ 学员姓名+身体健康申明.jpg
```

非法文件名字符替换为下划线。两个姓名相同，或净化后同名时，现有 ZIP 路径会冲突。修复前分别下载人工区分；未来消歧方案须同时满足命名和数据完整性要求。
